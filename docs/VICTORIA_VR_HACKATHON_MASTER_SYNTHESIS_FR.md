# 1. Résumé exécutif

Victoria VR évolue d’un projet de métavers/jeu vers une **plateforme d’AI-native immersive computing** structurée en trois grandes couches :

```text
CREATION
VR AI Builder

+

INTELLIGENCE
AI Avatars / AI Agents / Intelligence Core

+

RUNTIME & DISTRIBUTION
AI Verse
```

Le hackathon 2026 est cohérent avec cette évolution. Le défi officiel est désormais :

> **Turn plain language into interactive 3D scenes and working logic.**

La soumission doit être browser-based, réellement fonctionnelle, permettre à l’utilisateur d’interagir avec le résultat ou de continuer à le façonner, et montrer un rôle significatif de l’IA.

Le concours est aussi explicitement un moyen pour Victoria VR d’identifier des builders et projets pouvant mener à de futures collaborations.

La stratégie recommandée est donc de ne **pas** faire un simple clone de leur Builder, ni un énième « prompt → monde 3D ». La génération 3D va rapidement devenir une commodité si tous les concurrents utilisent les mêmes LLMs multimodaux.

Le centre de gravité de WorldPilot doit devenir :

> **AI Experience Engineering for interactive 3D worlds.**

La thèse :

> **From prompt to proof.**

WorldPilot doit permettre :

```text
CREATE
prompt → scene + working logic

PROGRAM
point + language → contextual behavior

SPECIFY
natural-language goals → Experience Contract

PROVE
World CI + simulation + counterexamples

IMPROVE
diagnose → minimal patch → retest
```

La signature UX `this / that / here / there` reste très forte, mais le moat intellectuel devient plus large : appliquer les principes de développement logiciel, de QA, de CI, de tests, d’observabilité et d’optimisation continue aux mondes 3D générés par IA.

# 2. La thèse centrale sur Victoria VR

Victoria VR semble suivre une trajectoire analogue à celle du Web :

```text
1. construire soi-même des expériences
2. permettre aux utilisateurs de construire
3. permettre à l’IA de construire
4. ajouter des agents capables d’habiter/tester
5. publier partout
6. mesurer l’usage réel
7. industrialiser la qualité et l’amélioration
```

La septième étape n’est pas annoncée officiellement sous ce nom. C’est une **inférence stratégique** basée sur l’évolution publique de Victoria VR.

Le problème futur devient :

> Une fois que des milliers de mondes peuvent être générés facilement, comment savoir lesquels fonctionnent réellement, lesquels atteignent leurs objectifs, et lesquels sont prêts à être publiés ?

WorldPilot peut occuper exactement cette couche.

# 18. WorldIR

WorldIR devient une pièce centrale.

## Pourquoi

Une scène 3D traditionnelle connaît :
- mesh ;
- transform ;
- material ;
- texture.

WorldPilot doit connaître :
- entity ;
- semantic role ;
- capability ;
- state ;
- rule ;
- objective ;
- zone ;
- constraint ;
- metric ;
- relationship.

Exemple :

```text
Battery B-17

semantic type:
replaceable battery

capabilities:
movable
inspectable
installable

state:
inspected = false
installed = false

relationships:
installTarget = rover

constraints:
mustBeInspectedBeforeInstallation

business importance:
mandatory training step
```

## Structure conceptuelle

```text
                       WorldIR

          ┌──────────────┼───────────────┐
          ▼              ▼               ▼
       GEOMETRY        LOGIC         SEMANTICS

       entities        rules         roles
       transforms      states        affordances
       zones           events        objectives
       assets          actions       constraints
                                      metrics
```

## Pourquoi c’est stratégique

WorldIR rend le système :
- renderer-agnostic ;
- model-agnostic ;
- testable ;
- diffable ;
- portable ;
- compatible avec des adapters futurs.

# 19. Experience Contract

C’est le pont entre intention humaine et preuve.

## Exemple

```text
EXPERIENCE CONTRACT

Purpose
Train a first-time rover technician.

SUCCESS
completion >= 90%

TIME
median completion < 120 sec

SAFETY
inspection cannot be bypassed
airlock cannot open before diagnostics

DISCOVERABILITY
critical controls discovered >= 95%
```

## Quatre couches recommandées

### Correctness
Le monde peut-il fonctionner ?

### Usability
Un humain comprend-il quoi faire ?

### Effectiveness
Le monde atteint-il le résultat attendu ?

### Platform Readiness
Le monde est-il compatible avec les surfaces ciblées ?

## Pourquoi c’est parfaitement aligné Victoria

Victoria conseille déjà à ses clients business :
- outcome ;
- metric ;
- iteration.

WorldPilot rend ces objectifs **exécutables**.

# 20. Natural-Language Properties

Une instruction peut être interprétée comme une propriété à maintenir.

Exemple :

> **Nobody should ever complete this training without inspecting the battery.**

Compilation conceptuelle :


Ce n’est plus seulement :
- génération ;

# 21. World CI

World CI est l’idée de CI appliquée aux expériences.

Exemple :

```text
WORLD CI
────────────────────────────

Logic integrity             PASS
No unreachable objective   PASS
No infinite cycles          PASS
Safety sequence             FAIL

Completion                  71%
Target                      ≥90%

NOT READY TO PUBLISH
```

Après correction :

```text
WORLD CI
────────────────────────────

Logic integrity             PASS
Safety sequence             PASS
Completion                  94%
Target                      ≥90%
Regression suite            47/47 PASS

READY TO PUBLISH
```

Le point important est la **preuve**.

Pas un LLM qui affirme :

> « cela semble mieux »

mais :
- tests ;

# 23. Counterexamples

- reproductible ;
- testable ;
- sauvegardable.

# 24. Ghost Replay

Les ghosts ne doivent pas être présentés comme le produit.

Victoria possède déjà des agents.

Les ghosts servent de :

> **replayable evidence**

Commande :

```text
Show me.
```

Le ghost rejoue exactement le bug dans la scène.

C’est un moment visuel très fort.

Principe :

> **No AI claim without evidence.**

Toute affirmation importante devrait être reliée à :
- trace ;
- state ;
- rule graph ;
- metric ;
- replay ;
- observation visuelle.

# 25. Regression Suite

Chaque bug détecté peut devenir un test permanent.

Exemple :

```text
REGRESSION TEST #17

Property:
Airlock cannot open unless
batteryInspected == true.

Counterexample previously found:
Start → Install → Diagnostics → Exit
```

Après toute modification :

```text
run affected tests
```

C’est le passage clé de « démo IA » à « engineering system ».

# 26. WorldDiff

Une modification du monde doit être inspectable.

Exemple :

```text
WORLD DIFF

+ Scanner moved 1.8m toward rover
+ Contextual highlight added
+ Installation now requires inspection

- No unrelated logic removed

Affected tests: 12
Regression: PASS
```

L’IA ne doit pas produire des modifications opaques.

# 27. Synthetic Users

La simulation doit avoir plusieurs niveaux.

## Level 1 — Formal graph

Très rapide :
- reachability ;
- dependency ;
- invariants ;
- deadlocks ;
- bypass ;
- cycles.

## Level 2 — Synthetic profiles

Profils :
- novice ;
- impatient ;
- curious ;
- explorer ;
- goal-driven.

Simulation rapide, stochasticité contrôlée.

## Level 3 — High-fidelity agent

Petit nombre de runs coûteux :
- vision ;
- spatial reasoning ;
- comportement plus libre ;
- model multimodal avancé.

Architecture recommandée :

```text
large formal coverage
+
medium synthetic population
+
few high-fidelity AI sessions
```

Pas :
- 100 agents LLM coûteux simultanés.

# 99. Questions possibles de Victoria — réponses

## « Pourquoi ne pas mettre cela directement dans notre Builder ? »
Réponse souhaitée :
> C’est exactement le point. WorldPilot est conçu comme une capability intégrable, pas comme une plateforme concurrente.

## « Pourquoi WorldIR ? »
> Pour découpler l’intention, la logique, la simulation et le renderer.

## « Pourquoi des ghosts si nous avons déjà des agents ? »
> Les ghosts ne sont pas le produit ; ils rendent les preuves et contre-exemples visibles. Vos agents pourraient être une source de traces beaucoup plus riche.

## « Pourquoi un runtime custom ? »
> Pour une démo browser déterministe. La logique est séparée via un adapter afin de ne pas lier le concept à R3F.

## « Est-ce vraiment générique ? »
> Judge suite multi-domaines + catalog générique + tests publics.

## « Est-ce que les résultats sont fiables ? »
> Les checks déterministes sont séparés des évaluations probabilistes, et chaque diagnostic important est lié à une preuve/replay.
